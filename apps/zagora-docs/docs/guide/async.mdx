---
title: Async support
description: When a zagora procedure returns a result and when it returns a promise, for sync and async handlers, schemas, and cache adapters.
---

The zagora source has no `async` or `await`. zagora checks for promises at runtime, and a procedure becomes async only when a part of it is async. The return type follows the same rules, so the type of a sync procedure is not a `Promise`.

The table shows what each async part does to the procedure.

| What is async | Procedure returns | Type |
| --- | --- | --- |
| Nothing | `Result` | `Result` |
| An `async` handler | always a `Promise` | `Promise<Result>` |
| A handler that returns a promise | a `Promise` when the handler runs | `Promise<Result>` |
| A schema marked `async: true`, such as a Valibot async schema | always a `Promise` | `Promise<Result>` |
| A Zod schema with an async refinement | a `Promise` | `Result`, so `await` it anyway |
| A cache adapter method | a `Promise` when the method runs | `Result \| Promise<Result>` |

## An async handler makes every call async

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const syncProc = zagora()
  .input(z.string())
  .handler((_, input) => input.toUpperCase())
  .callable();

const asyncProc = zagora()
  .input(z.string())
  .handler(async (_, input) => input.toUpperCase())
  .callable();

const a = syncProc("hello");
//    ^?

const b = asyncProc("hello");
//    ^?
```

An `async` handler makes every call return a `Promise`. That includes the calls that fail before the handler runs. A plain function that returns a promise makes a call async only when the handler runs. zagora awaits a thenable that is not a native `Promise`, such as a query builder, in the same way.

## A schema marked async makes every call async

The Standard Schema type does not say whether a schema is async. zagora reads the `async: true` marker that some libraries put on async schemas, such as the Valibot `pipeAsync` and `objectAsync` schemas. The marked schema can be the input schema, the output schema, or any entry of the error map. The procedure then always returns a `Promise`, and its type says so.

```ts twoslash
import * as v from "valibot";
import { zagora } from "zagora";
// ---cut---
const checkName = zagora()
  .input(
    v.pipeAsync(
      v.string(),
      v.checkAsync(async (name) => name !== "taken"),
    ),
  )
  .handler((_, name) => name)
  .callable();

const result = checkName("ada");
//    ^?
```

## Zod async refinements are async only at runtime

Zod schemas have no `async: true` marker. A Zod schema with an async refinement still makes the call return a `Promise` at runtime, but the type cannot show it. When you know that a schema is async, always `await` the call. Your editor may say that `await` has no effect there. You still need it. The [Standard Schema issue about async detection](https://github.com/standard-schema/standard-schema/issues/22) has the upstream discussion.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const longText = zagora()
  .input(z.string().refine(async (value) => value.length > 10))
  .handler((_, input) => input)
  .callable();

const result = await longText("hello");
```

ArkType has no async schemas, so it does not have this problem.

## An async cache adapter makes some calls async

An async cache method makes a call async only when that call runs the method. A call with invalid input fails before the cache and stays sync. For that reason, the type is `Result | Promise<Result>`. The [caching guide](/guide/caching) has the details.

## Env schemas cannot be async

zagora does not support async env schemas. The [environment variables guide](/guide/environment-variables) shows the error that you get.

## Await every call when any part can be async

When any part of a procedure can be async, `await` every call. An `await` on a sync result does no harm.
