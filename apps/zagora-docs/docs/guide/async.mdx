---
title: Async support
description: When a zagora procedure returns a result and when it returns a promise, for sync and async handlers, schemas, and cache adapters.
---

zagora has no `async`/`await` in its code. It checks for promises at runtime, and a procedure becomes async only when a part of it is async. The return type follows the same rules, so a sync procedure is not typed as a `Promise`.

| What is async | Procedure returns | Type |
| --- | --- | --- |
| Nothing | `Result` | `Result` |
| An `async` handler | always a `Promise` | `Promise<Result>` |
| A handler that returns a promise | a `Promise` when the handler runs | `Promise<Result>` |
| A schema marked `async: true`, such as a Valibot async schema | always a `Promise` | `Promise<Result>` |
| A Zod schema with an async refinement | a `Promise` | `Result`, so `await` it anyway |
| A cache adapter method | a `Promise` when the method runs | `Result \| Promise<Result>` |

## Handlers

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const syncProc = zagora()
  .input(z.string())
  .handler((_, input) => input.toUpperCase())
  .callable();

const asyncProc = zagora()
  .input(z.string())
  .handler(async (_, input) => input.toUpperCase())
  .callable();

const a = syncProc("hello");
//    ^?

const b = asyncProc("hello");
//    ^?
```

An `async` handler makes every call return a `Promise`, also the calls that fail before the handler runs. A plain function that returns a promise does the same when it runs. A thenable that is not a native `Promise`, such as a query builder, is awaited like one.

## Schemas

The Standard Schema type does not say whether a schema is async. zagora reads the `async: true` marker that some libraries put on async schemas, such as Valibot's `pipeAsync` and `objectAsync`. A procedure with such a schema, in the input, the output, or any entry of the error map, always returns a `Promise`, and its type says so.

```ts twoslash
import * as v from "valibot";
import { zagora } from "zagora";
// ---cut---
const checkName = zagora()
  .input(
    v.pipeAsync(
      v.string(),
      v.checkAsync(async (name) => name !== "taken"),
    ),
  )
  .handler((_, name) => name)
  .callable();

const result = checkName("ada");
//    ^?
```

Zod has no such marker. A Zod schema with an async refinement still makes the call return a `Promise` at runtime, but the type cannot show it. When you know that a schema is async, always `await` the call. Your editor may say that `await` has no effect there. You still need it. The upstream discussion is [Standard Schema issue #22](https://github.com/standard-schema/standard-schema/issues/22).

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const longText = zagora()
  .input(z.string().refine(async (value) => value.length > 10))
  .handler((_, input) => input)
  .callable();

const result = await longText("hello");
```

ArkType has no async schemas, so it does not have this problem.

## Cache adapters

An async cache method makes a call async only when that call runs the method. A call with invalid input fails before the cache and stays sync. That is why the type is `Result | Promise<Result>`. See [caching](/guide/caching).

## Environment variables

Async env schemas are not supported. See [environment variables](/guide/environment-variables).

## Rule of thumb

When any part of a procedure can be async, `await` every call. `await` on a sync result is harmless.
