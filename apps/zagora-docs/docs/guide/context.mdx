---
title: Context
description: Pass typed dependencies, such as a database, a request, or the current user, to handlers, at definition time or at call time.
---

Context is typed dependency injection. Set its type, and an optional initial value, with `.context()`. The handler reads it from `options.context`.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const procedure = zagora()
  .context<{ userId: string; foo?: string }>({ userId: "default" })
  .input(z.string())
  .handler(({ context }, id) => {
    //        ^?
    return `${context.userId} has foo -> ${context.foo ?? "unknown"}, id = ${id}`;
  })
  .callable({ context: { userId: "foo-bar", foo: "qux" } });

procedure("charlie");
// { ok: true, data: 'foo-bar has foo -> qux, id = charlie', error: undefined }
```

## Definition time and call time

You can give the context in two places:

- `.context(initial)` when you define the procedure
- `.callable({ context })` when you make the function

The second place is useful when the values exist only where the call happens, for example in a `fetch` handler that has the request and the logged-in user. Define the procedures once, and make them callable per request.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";

type Db = { findUser(id: string): { id: string; name: string } | undefined };
declare function getDb(env: unknown): Db;
// ---cut---
const getUser = zagora()
  .context<{ db: Db }>()
  .input(z.string())
  .handler(({ context }, id) => context.db.findUser(id));

export default {
  fetch(request: Request, env: unknown) {
    const id = new URL(request.url).searchParams.get("id") ?? "";
    const result = getUser.callable({ context: { db: getDb(env) } })(id);
    return Response.json(result);
  },
};
```

`.context<T>()` with no value only sets the type. Then pass the value with `.callable()`.

## How the two values merge

zagora deep-merges the call-time context into the initial context. Plain objects merge key by key. Any other value, such as a class instance, an array, or a `Map`, replaces the initial value as it is, so a database client keeps its prototype and methods.

```ts twoslash
import { zagora } from "zagora";
// ---cut---
class Database {
  constructor(readonly name: string) {}
}

type Context = {
  db: Database;
  config: { timeout?: number; retries?: number };
};

const procedure = zagora()
  .context<Context>({
    db: new Database("production"),
    config: { timeout: 5, retries: 1 },
  })
  .handler(({ context }) => ({ db: context.db.name, config: context.config }))
  .callable({
    context: { db: new Database("test"), config: { retries: 2 } },
  });

procedure();
// { ok: true, data: { db: 'test', config: { timeout: 5, retries: 2 } }, error: undefined }
```

The context root must be a plain object. TypeScript rejects other values.

## Context with auto-callable

With `autoCallable: true` there is no `.callable()` call, so the handler gets only the initial context from `.context()`. See [instance options](/guide/instance-options).

## Context with disableOptions

With `disableOptions: true` the handler gets no options object, so it has no access to the context.
