---
title: Caching
description: Memoize procedures with any cache adapter that has has, get, and set methods, sync or async, and learn how the cache key is built.
---

Give a procedure a cache adapter, and zagora stores each validated output under a key built from the call. The next call with the same arguments returns the stored output without running the handler.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const cache = new Map();

const upper = zagora()
  .input(z.string())
  .handler((_, input) => input.toUpperCase())
  .callable({ cache });

upper("hello"); // runs the handler
upper("hello"); // returns the stored output
```

A `Map` works as an adapter as it is. Any object with these methods works too:

```ts
type CacheAdapter = {
  has(key: string): boolean | Promise<boolean>;
  get(key: string): unknown;
  set(key: string, value: unknown): any;
};
```

## Where to pass the cache

Pass the adapter with `.cache(adapter)` when you define the procedure, or with `.callable({ cache })` when you make the function. A cache passed to `.callable()` replaces the one from `.cache()`. Passing it at call time is useful when the cache comes from the runtime, for example a KV binding in a `fetch` handler.

## Async adapters

Any adapter method can be async. Then the procedure can return a `Promise`, and its type is `Result | Promise<Result>`. It is not always a promise, because a call that fails before it reaches the cache, such as one with invalid input, stays sync. Always `await` such a procedure.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const store = new Map<string, unknown>();

const double = zagora()
  .cache({
    async has(key: string) {
      return store.has(key);
    },
    get(key: string) {
      return store.get(key);
    },
    set(key: string, value: unknown) {
      store.set(key, value);
    },
  })
  .input(z.number())
  .handler((_, num) => num * 2)
  .callable();

const result = await double(22);
//    ^?
```

## What gets stored

- Only output that passed the output schema is stored. A failed call never writes to the cache.
- A cache hit returns the stored output as it is, without validating it again.
- A stored value of `undefined` counts as a miss. If an entry expires between `has` and `get`, the handler runs again.

## The cache key

The key is a SHA-256 hash of a JSON string. The JSON holds the handler arguments after validation, the input, output, error, and env schemas, and the source text of the handler. Unless `disableOptions` is on, the handler arguments include the options object, so the context and the env values are part of the key too. A `bigint` argument is encoded so that it does not collide with a string of the same digits.

JSON has limits, so keep these in mind:

- `undefined` and `null` in an argument list can give the same key. Cache only procedures whose arguments JSON keeps apart.
- The source text of the handler does not include the variables it captures. Schema functions, such as refinements and transforms, do not appear in JSON either.
- Two procedures that differ only in captured state or schema functions can share keys. Give each of them its own cache instance.

The hash uses `node:crypto`. On Cloudflare Workers, turn on the `nodejs_compat` flag.

## Cache failures

A cache adapter that throws or rejects does not crash the call. The result has an `UNKNOWN_ERROR` with the original error in `cause`, and a message that names the method, such as `Failure in CacheAdapter.has method` or `Failure in async CacheAdapter.set method`. When the key cannot be computed, for example for a circular argument or context value, the message is `Failed to compute cache key`.
