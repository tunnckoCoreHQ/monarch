---
title: Tuple arguments
description: Use a tuple schema to give a procedure several arguments, each one validated, with defaults and optional trailing arguments.
---

A tuple input schema turns into a list of function arguments. Each element of the tuple is one argument. zagora validates each one, fills in defaults, and passes them to the handler as separate parameters.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const introduce = zagora()
  .input(z.tuple([z.string(), z.number().default(18), z.string().optional()]))
  .handler((_, name, age, country) => {
    //                 ^?
    return `${name} is ${age}, from ${country ?? "unknown"}`;
  })
  .callable();

introduce("Barry");
// 'Barry is 18, from unknown'
introduce("Barry", 25);
// 'Barry is 25, from unknown'
introduce("Barry", 33, "USA");
// 'Barry is 33, from USA'
```

## The signature

The procedure gets a real parameter list. A trailing element that accepts `undefined`, because it has a default or is optional, becomes an optional parameter. Required elements stay required.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";

const introduce = zagora()
  .input(z.tuple([z.string(), z.number().default(18), z.string().optional()]))
  .handler((_, name, age, country) => `${name} ${age} ${country}`)
  .callable();
// ---cut---
introduce;
// ^?
```

In the handler, an element with a default has its output type, so `age` is a `number`. An optional element without a default is `string | undefined`.

## Errors per argument

TypeScript reports a wrong or missing argument at compile time. At runtime, zagora still validates every call, and the issue path tells you which argument failed. Index `0` is the first argument.

```ts twoslash
// @errors: 2345 2554
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const pair = zagora()
  .input(z.tuple([z.string(), z.number()]))
  .handler((_, name, count) => `${name} x${count}`)
  .callable();

pair("John", "foo");
// error.message: 'Input validation failed: 1 => expected number, received string'

pair("John");
// error.message: 'Input validation failed: (root) => Too small: expected array to have >=2 items'
```

## Valibot tuples

Valibot works the same way. An optional element with a default value, `v.optional(schema, value)`, is filled in when the argument is missing.

```ts twoslash
import * as v from "valibot";
import { zagora } from "zagora";
// ---cut---
const range = zagora()
  .input(v.tuple([v.number(), v.optional(v.number(), 10)]))
  .handler((_, start, end) => ({ start, end }))
  .callable();

range(1);
// { ok: true, data: { start: 1, end: 10 }, error: undefined }
```

## Tuples with transforms

A tuple piped into a transform still spreads, as long as the transform returns a tuple. If the transform returns something that is not an array, the handler gets it as one argument.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const swap = zagora()
  .input(
    z
      .tuple([z.string(), z.number()])
      .transform(([name, count]) => [count, name] as [number, string]),
  )
  .handler((_, count, name) => `${name}: ${count}`)
  .callable();

swap("apples", 3);
// { ok: true, data: 'apples: 3', error: undefined }
```

## Without the options object

With `disableOptions: true`, the tuple elements are the only handler parameters. This is the most compact way to write small functions. See [instance options](/guide/instance-options).

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const za = zagora({ autoCallable: true, disableOptions: true });

export const add = za.input(z.tuple([z.number(), z.number()])).handler((a, b) => a + b);
export const sub = za.input(z.tuple([z.number(), z.number()])).handler((a, b) => a - b);

add(5, 3);
// { ok: true, data: 8, error: undefined }
```
