---
title: Tuple arguments
description: Use a tuple schema to give a procedure several arguments, each one validated, with defaults and optional trailing arguments.
---

A tuple input schema gives the procedure several arguments. Each element of the tuple is one argument. zagora validates every argument, fills in the defaults, and passes the arguments to the handler as separate parameters.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const introduce = zagora()
  .input(z.tuple([z.string(), z.number().default(18), z.string().optional()]))
  .handler((_, name, age, country) => {
    // name: string, age: number, country: string | undefined
    return `${name} is ${age}, from ${country ?? "unknown"}`;
  })
  .callable();

introduce("Barry");
// 'Barry is 18, from unknown'
introduce("Barry", 25);
// 'Barry is 25, from unknown'
introduce("Barry", 33, "USA");
// 'Barry is 33, from USA'
```

## The signature

The procedure gets a real parameter list. A trailing element with a default, or a trailing optional element, accepts `undefined`, so it becomes an optional parameter. Required elements stay required.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";

const introduce = zagora()
  .input(z.tuple([z.string(), z.number().default(18), z.string().optional()]))
  .handler((_, name, age, country) => `${name} ${age} ${country}`)
  .callable();
// ---cut---
introduce;
// (name: string, age?: number, country?: string) => result
```

In the handler, an element with a default has its output type, so `age` is a `number`. An optional element without a default is `string | undefined`.

## Errors per argument

TypeScript reports a wrong or missing argument at compile time. At runtime, zagora still validates every call. For a wrong argument, the issue path is the index of that argument, and index `0` is the first argument. For a missing argument, the issue is on `(root)`, the whole list.

```ts twoslash
// @errors: 2345 2554
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const pair = zagora()
  .input(z.tuple([z.string(), z.number()]))
  .handler((_, name, count) => `${name} x${count}`)
  .callable();

pair("John", "foo");
// error.message: 'Input validation failed: 1 => expected number, received string'

pair("John");
// error.message: 'Input validation failed: (root) => Too small: expected array to have >=2 items'
```

## Valibot tuples

Valibot tuples work the same way. For an element written as `v.optional(schema, value)`, zagora passes `value` when the argument is missing.

```ts twoslash
import * as v from "valibot";
import { zagora } from "zagora";
// ---cut---
const range = zagora()
  .input(v.tuple([v.number(), v.optional(v.number(), 10)]))
  .handler((_, start, end) => ({ start, end }))
  .callable();

range(1);
// { ok: true, data: { start: 1, end: 10 }, error: undefined }
```

## Tuples with transforms

A Zod tuple with a transform still spreads when the transform returns a tuple. When the transform returns a value that is not an array, the handler gets that value as one argument.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const swap = zagora()
  .input(
    z
      .tuple([z.string(), z.number()])
      .transform(([name, count]) => [count, name] as [number, string]),
  )
  .handler((_, count, name) => `${name}: ${count}`)
  .callable();

swap("apples", 3);
// { ok: true, data: 'apples: 3', error: undefined }
```

## Without the options object

With `disableOptions: true`, the tuple elements are the only handler parameters. The handler then has no `errors`, `context`, or `env`, so the option suits small functions. The [instance options](/guide/instance-options) page has the details.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const za = zagora({ autoCallable: true, disableOptions: true });

export const add = za.input(z.tuple([z.number(), z.number()])).handler((a, b) => a + b);
export const sub = za.input(z.tuple([z.number(), z.number()])).handler((a, b) => a - b);

add(5, 3);
// { ok: true, data: 8, error: undefined }
```
