---
title: Optional and default values
description: Schema defaults and optional fields work at every level, in tuple arguments, object fields, primitive inputs, error data, and environment variables.
---

zagora reads defaults and optionals from your schema. The caller can leave the value out, and the handler gets the filled-in value with a precise type.

## In objects

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const profile = zagora()
  .input(
    z.object({
      name: z.string(),
      age: z.number().default(18),
      country: z.string().optional(),
    }),
  )
  .handler((_, input) => input)
  //           ^?
  .callable();

profile({ name: "John" });
// { ok: true, data: { name: 'John', age: 18 }, error: undefined }
```

The caller's type has `age?: number`, and the handler's type has `age: number`.

## In tuple arguments

A missing trailing argument gets its default before validation. See [tuple arguments](/guide/tuple-arguments).

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const repeat = zagora()
  .input(z.tuple([z.string(), z.number().default(2), z.string().default(" ")]))
  .handler((_, text, times, separator) => Array(times).fill(text).join(separator))
  .callable();

repeat("ha");
// { ok: true, data: 'ha ha', error: undefined }
repeat("ha", 3, "-");
// { ok: true, data: 'ha-ha-ha', error: undefined }
```

A tuple in which every element is optional or has a default also works. Then the procedure can be called with no arguments at all.

## In a primitive input

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const double = zagora()
  .input(z.number().default(10))
  .handler((_, value) => value * 2)
  .callable();

double(undefined);
// { ok: true, data: 20, error: undefined }
```

<Callout type="note">
  The argument of a primitive input with a default is still required at the type level, so pass
  `undefined` to use the default. A tuple input makes trailing arguments truly optional.
</Callout>

## In error data and environment variables

Defaults also apply to the data of [typed errors](/guide/typed-errors) and to [environment variables](/guide/environment-variables). An error helper does not require a field that has a default, and the default appears in `result.error`.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const limited = zagora()
  .errors({
    RATE_LIMIT: z.object({
      retryAfter: z.number(),
      limit: z.number().default(1000),
    }),
  })
  .handler(({ errors }) => {
    throw errors.RATE_LIMIT({ retryAfter: 120 });
  })
  .callable();

limited();
// { ok: false, isTypedError: true, error: { retryAfter: 120, limit: 1000, kind: 'RATE_LIMIT' } }
```
