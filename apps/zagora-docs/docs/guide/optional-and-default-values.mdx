---
title: Make values optional or give them defaults
description: Where schema defaults and optional values apply, and how they change the types of the caller and the handler.
---

Zagora takes defaults and optional values from your schema. The caller can leave out a value that has a default, and the handler gets the default. In the handler's type, a value with a default is never `undefined`.

## Make object keys optional

Give an object key a `.default()` or make it `.optional()`, and the caller can leave the key out. A key with a default always has a value in the handler, so its type there is not optional. In this example, the caller's type has `age?: number`, and the handler's type has `age: number`.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const profile = zagora()
  .input(
    z.object({
      name: z.string(),
      age: z.number().default(18),
      country: z.string().optional(),
    }),
  )
  .handler((_, input) => input)
  // input: { name: string; age: number; country?: string }
  .callable();

profile({ name: "John" });
// { ok: true, data: { name: 'John', age: 18 }, error: undefined }
```

## Make trailing arguments optional

In a [tuple](/guide/tuple-arguments), an element with a default or an `.optional()` element becomes an optional parameter, as long as every element after it is optional too. A missing argument gets its default before the handler runs. When every element is optional, you can call the procedure with no arguments.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const repeat = zagora()
  .input(z.tuple([z.string(), z.number().default(2), z.string().default(" ")]))
  .handler((_, text, times, separator) => Array(times).fill(text).join(separator))
  .callable();

repeat("ha");
// { ok: true, data: 'ha ha', error: undefined }
repeat("ha", 3, "-");
// { ok: true, data: 'ha-ha-ha', error: undefined }
```

## Make a single argument optional

A non-tuple input schema with a `.default()` makes the one argument optional, because its input type accepts `undefined`. An `.optional()` schema works the same way. Without the argument, the handler gets the default, or `undefined` for an `.optional()` schema.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const double = zagora()
  .input(z.number().default(10))
  .handler((_, value) => value * 2)
  .callable();

double();
// { ok: true, data: 20, error: undefined }
```

## Give defaults to error data and env values

Defaults also apply to the data of [typed errors](/guide/typed-errors) and to [environment variables](/guide/environment-variables). An error helper does not require a field that has a default, and `result.error` has the default value.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";
// ---cut---
const limited = zagora()
  .errors({
    RATE_LIMIT: z.object({
      retryAfter: z.number(),
      limit: z.number().default(1000),
    }),
  })
  .handler(({ errors }) => {
    throw errors.RATE_LIMIT({ retryAfter: 120 });
  })
  .callable();

limited();
// { ok: false, isTypedError: true, error: { retryAfter: 120, limit: 1000, kind: 'RATE_LIMIT' } }
```
