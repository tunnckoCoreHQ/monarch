zagora is a small TypeScript library for functions that never throw. You describe the input, the output, and the errors with any [Standard Schema](https://standardschema.dev) library, such as Zod, Valibot, or ArkType. zagora gives you back a plain function. Every call returns a result object, either `{ ok: true, data }` or `{ ok: false, error }`.

```ts twoslash
import { z } from "zod";
import { zagora } from "zagora";

const getUser = zagora()
  .input(z.tuple([z.string(), z.number().default(18)]))
  .output(z.object({ name: z.string(), age: z.number(), email: z.string() }))
  .handler((_, name, age) => {
    // name: string, age: number
    return { name, age, email: `${name.toLowerCase()}@example.com` };
  })
  .callable();

const result = getUser("Charlie");

if (result.ok) {
  console.log(result.data);
  // { name: 'Charlie', age: 18, email: 'charlie@example.com' }
} else {
  console.error(result.error.kind);
  // kind: "UNKNOWN_ERROR" | "VALIDATION_ERROR"
}
```

The second argument has a default in the schema, so `getUser("Charlie")` is a valid call. The handler gets `age` as a `number`, not `number | undefined`.

## Why zagora

[oRPC](https://orpc.dev) and [tRPC](https://trpc.io) build procedures for APIs, with a router, a server, a client, and a network between them. zagora keeps only the procedure. It is a lower-level tool for libraries, SDKs, CLIs, and the internals of an app. The result is a regular TypeScript function that you export and call.

- **Never throws.** Validation failures, thrown errors, rejected promises, and failing cache adapters all come back as `result.error`.
- **Typed errors.** You declare error kinds with schemas. Handlers get a typed helper for each kind, and callers get a discriminated union of every kind.
- **Real function signatures.** A tuple schema becomes a list of arguments, with validation, defaults, and optional trailing arguments for each one.
- **Sync stays sync.** A sync handler with sync schemas and a sync cache adapter gives a sync procedure. A handler with the `async` keyword, or a schema marked `async: true`, gives a procedure that returns a `Promise` on every call. A plain handler that returns a promise makes only the calls that reach it async. See [async support](/guide/async) for every case.
- **No unwrapping.** You read `result.data` or `result.error` directly. With neverthrow, you unwrap a `Result` first.
- **Typed dependencies.** You set the context, the environment variables, and the cache adapter when you define the procedure or when you make it callable.
- **Tested types.** The types have their own test suite, next to the runtime tests.
