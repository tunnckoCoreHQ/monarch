zagora keeps the procedure builder from [oRPC](https://orpc.dev) and [tRPC](https://trpc.io), and removes the router, the server, the client, and the network. It is for code that calls functions, not endpoints.

## At a glance

|  | zagora | oRPC and tRPC | neverthrow | Effect |
| --- | --- | --- | --- | --- |
| Output | A plain function | A procedure in a router | A `Result` wrapper | An `Effect` value |
| Network layer | None | Built in | None | Optional |
| Router | Not needed, use a plain object | Required to serve | None | None |
| Arguments | Any number, from a tuple schema | One input value | Any | Any |
| Sync calls | Sync handlers return a sync result | Calls return a `Promise` | Yes | Yes |
| Runtime validation | Standard Schema | Standard Schema | Not included | Effect Schema |
| Typed errors | Declared with schemas | oRPC declares them with schemas. tRPC has fixed error codes | From types | From types |
| Unwrapping | None, read `result.data` | None | Required | Required to run |
| Middleware | None | Built in | None | Layers and services |

## oRPC and tRPC

oRPC and tRPC are frameworks for APIs. Both let you call a procedure on the server too. oRPC has `.callable()` and `createRouterClient`, and tRPC has `createCaller`. Those calls still bring the router, the protocol, and the async contract. zagora is the smaller tool for when you want only the function.

- **The function is the product.** The `.callable()` method returns a function with the signature that the input schema describes. There is nothing to mount or serve.
- **Several arguments.** An oRPC or tRPC procedure takes one input value. In zagora, the tuple schema `z.tuple([z.string(), z.number().default(10)])` gives `(name: string, count?: number)`, and each argument gets its own validation and default. See [tuple arguments](/guide/tuple-arguments).
- **Sync stays sync.** The zagora source has no `async` or `await`. It checks for promises at runtime, so a sync handler with sync schemas and a sync cache adapter gives a sync result. The return type follows the same rules. See [async support](/guide/async) for every case.
- **Errors are values.** A `SyntaxError` that a handler throws comes back as an `UNKNOWN_ERROR`, with the `SyntaxError` in `result.error.cause`. The caller has no error class to catch.
- **No middleware.** Do that work before the call, and pass the outcome as [context](/guide/context). The [routers recipe](/recipes/routers) shows how to group procedures, and the [HTTP handlers recipe](/recipes/http-handlers) shows how to serve them.

Use oRPC or tRPC when you need a typed client over HTTP, OpenAPI, or streaming. Use zagora for libraries, SDKs, CLIs, and the internal functions of an app. The two also work together, because an oRPC handler can call a zagora procedure.

## neverthrow

neverthrow returns a `Result` that you unwrap with `match`, `map`, or `isOk()`. zagora returns a plain discriminated union. You check `result.ok`, and TypeScript narrows `result.data` and `result.error`. zagora also validates the input and the output at runtime. neverthrow does no validation.

## Effect

Effect is a full runtime with its own model for errors, dependencies, concurrency, and resources. It does a lot, and you must learn its model to use it. zagora covers two parts of that model, typed errors and typed dependencies, with plain functions and plain objects.

## Plain TypeScript functions

TypeScript checks types at compile time only. Data from users, files, the network, or `process.env` can still have the wrong shape at runtime. The function then throws or returns a wrong value. zagora validates at runtime with the same schema that gives the types, and returns one result shape for every failure.

## Schema libraries on their own

You can call `schema.safeParse()` in every function. zagora puts that call in one place and adds the following:

- a builder for input, output, errors, context, environment variables, and cache
- several arguments from tuple schemas, with defaults filled in before the handler runs
- validation of the output and of the error data, not only the input
- one result shape for validation errors, thrown errors, and typed errors
- support for any Standard Schema library, and for more than one library in the same procedure
