```ts
import { isValidationError, isInternalError, isDefinedError, isZagoraError } from "zagora/errors";
```

The main entry has the same exports on its `errors` namespace, as in `import { errors } from "zagora"`.

## Guards

Each guard takes any value and returns a boolean.

| Function | Returns `true` when |
| --- | --- |
| `isValidationError(val)` | `kind` is `"VALIDATION_ERROR"`, `message` is a string, and `issues` is an array |
| `isInternalError(val)` | `kind` is `"UNKNOWN_ERROR"`, `message` is a string, and the `cause` and `stack` keys exist |
| `isDefinedError(val)` | `kind` is an uppercase string, and the other two guards return `false` |
| `isZagoraError(val)` | one of the three guards above returns `true` |

After `JSON.stringify`, an `UNKNOWN_ERROR` keeps its `cause` and `stack` keys only when they hold a value. Without them, `isInternalError` returns `false`, and `isDefinedError` returns `true`.

On an error union, such as `result.error`, each guard narrows to the members that match, and its `false` branch keeps the other members. On any other value, it narrows to the guarded error shape. The order of the checks does not matter. The [type guards section of the error handling guide](/guide/error-handling#narrow-an-error-with-a-type-guard) shows them in use.

## Failures and their kinds

Every failure of a step becomes a failed result. Zagora freezes each error object with `Object.freeze`.

| Failure | Kind |
| --- | --- |
| Invalid input, output, or env | `VALIDATION_ERROR` |
| A handler that throws or rejects with a declared kind and valid data | That kind, with `isTypedError` set to `true` |
| A handler that throws or rejects with a declared kind and invalid data | `VALIDATION_ERROR`, with the kind in `key` |
| A handler that throws or rejects with a kind that the error map does not declare | `UNKNOWN_ERROR` |
| A handler that throws or rejects with any other value | `UNKNOWN_ERROR`, with the thrown value in `cause` |
| A falsy thrown value, such as `throw undefined` or `throw 0` | `UNKNOWN_ERROR` |
| A schema that throws or rejects | `UNKNOWN_ERROR` |
| A [cache adapter](/guide/caching) method that throws or rejects | `UNKNOWN_ERROR` |
| A cache key that Zagora cannot compute | `UNKNOWN_ERROR` |
| An async env schema, which Zagora does not support | `UNKNOWN_ERROR` |
| A thrown value whose `kind` getter throws | `UNKNOWN_ERROR`, with the thrown value in `cause` |

Zagora runs the steps in this order: env, input, the cache key and the cache read, the handler, the output, and the cache write. It stops the call at the first step that fails. So the handler runs only with valid input, and the cache stores only valid output.

## Creators

Zagora builds its own errors with these functions.

### createValidationError(mode, issues, key?)

```ts
createValidationError<ErrorKindNames = never>(
  mode: "input" | "output" | "error data" | "env",
  issues: SchemaIssue[],
  key?: ErrorKindNames,
);
```

Returns `{ kind: "VALIDATION_ERROR", message, key, issues }`. The message has the form `<Mode> validation failed[ for KEY]: <path> => <message>; ...`. Each path is the keys of the issue path joined with dots, or `(root)` when the issue has no path. The first `Invalid input: ` in each issue message is removed.

### createInternalError(msg, cause?)

```ts
createInternalError(msg: string, cause?: any);
```

Returns `{ kind: "UNKNOWN_ERROR", message: msg, cause, stack }`. The `stack` is the `stack` of `cause`, or `undefined` when `cause` has no readable `stack`.

### createErrorHelpers(errorMap)

```ts
createErrorHelpers(errorMap: any): Record<string, (data: any) => any>;
```

Returns one helper for each key that `Object.keys` gives for the map. A key whose schema is falsy gets no helper. A helper returns `{ ...data, kind }`, and the key wins over a `kind` field in `data`.

## Types

| Type | Shape |
| --- | --- |
| `ValidationError<ErrorKindNames>` | `Readonly<{ kind: "VALIDATION_ERROR"; message: string; issues: readonly SchemaIssue[]; key?: ErrorKindNames }>` |
| `InternalError` | `Readonly<{ kind: "UNKNOWN_ERROR"; message: string; cause: any; stack: any }>`, the return type of `createInternalError` |
| `DefinedError<T>` | `{ readonly kind: string } & T` |
| `ZagoraError<T>` | `ValidationError \| InternalError \| DefinedError<T>` |
| `ErrorHelpers<TErrorsMap>` | The `options.errors` object. Each key has a `(data) => never` function, where `data` is the schema input without `kind`. |
| `InferSchemaMapPlain<T, ResolveErr>` | The output type of each schema in the map `T`. With `ResolveErr` set to `true`, each type also has `kind` set to its key. |
| `ResolveErrorKindNames<TErrorsMap>` | The union of the keys of `TErrorsMap`, or `undefined` without an error map |
